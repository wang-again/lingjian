# 报告撰写

先确定读者、用途、交付格式及用户指定章节。采用当前模板时保留其必要结构；没有模板时按任务选择结构，不强套统一章节。以实际提供的资料为依据，缺失的预算、日期、调查结果和负责人标为待补充。

普通写作的全文任务由应用先生成写作提纲，再据此起草正文。提纲应列出章节、可用依据和信息缺口；正文直接交付用户所需内容，不重复输出工作计划。大纲、续写、选区润色或审阅任务遵守所选任务范围，不能因为启用本技能而替换整篇文档。

文件智能体先读取选中文件，再组织报告和调用 write_docx。用户要求以当前正文为准时保留其中已确认的事实。区分事实、推断和建议，引用写成 [资料：文件名]；具体位置仅在读取结果确实提供时注明。

可使用 search_sources 从选中资料中检索写作依据，使用返回的 citation 标注实际位置，不编造页码。仅依据检索片段写作时说明检索覆盖范围；出现 warnings 时保留限制，按需读取上下文，不能声称已完整审阅全部资料。

Word 正文的 content_json 是 JSON 数组字符串；heading 使用 text，table 使用 headers/rows。工具指南中的绝对路径示例在本项目应替换为文件库相对 ID。生成后应用会自动调用 check_docx，检查结果会随写入结果返回。

发现结构错误时修复后再次检查。存在占位符或需确认事项时如实交付待完善稿，不编造内容来消除警告。正文逻辑和事实仍需审阅；结构检查通过不等于经过页式排版目检。
